# n8n workflows

## Первый запуск

1. Откройте n8n → **Workflows** → **Import from File**.
2. Выберите `01-intake-foundation.json`.
3. Для ручной проверки нажмите **Execute Workflow**; для Telegram включите workflow (`Active`).
4. В узле **Нормализовать заявку** убедитесь, что появились: `lead_id`, `created_at`, `normalized_text`, `message_hash` и `status: new`.
5. Последний узел **Подготовить подтверждение** должен вернуть только `accepted`, `lead_id` и `status`.

## Как читать workflow

Схема читается слева направо и разделена стикерами на три зоны:

1. **Входящие данные** — `Приём заявки из Telegram` принимает реального клиента. Ветка `Ручной запуск (проверка) → Тестовая заявка` нужна только для безопасной проверки.
2. **Подготовка** — `Нормализовать заявку` проверяет контакт и текст, создаёт ID и ключ для поиска дублей.
3. **Подтверждение** — `Подготовить подтверждение` завершает сценарий. Telegram-бот получает успешный HTTP-ответ только после этой точки.

Следующий этап сознательно не спрятан в этом MVP: после нормализации нужно последовательно добавить поиск дублей, AI-разбор, запись в Google Sheets и уведомление менеджеру.

## Если Telegram показывает подпись n8n

Подпись `This message was sent automatically with n8n` добавляет не Telegram-бот из этого репозитория, а активный узел **Telegram → Send Message** в другом workflow n8n. Откройте именно тот workflow, который отправляет сообщения в чат, и в его настройках отключите **Append Attribution**. Затем сохраните и активируйте этот workflow. В экспорт `01-intake-foundation.json` узел отправки сообщений не входит: он только принимает и готовит заявку.

В workflow есть два входа: **Тестовая заявка** для ручной проверки и **Приём заявки из Telegram** для бота. Webhook принимает `POST /webhook/telegram-lead`.

## Запись без дублей

После **Нормализовать заявку** подключите узел **Append or update row in sheet** по инструкции в `docs/google-sheets-setup.md`. Он сопоставляет строку по `message_hash` и использует автоматическое сопоставление одноимённых полей. Повтор одного и того же обращения обновляет найденную строку, а не создаёт новую.

Не включайте workflow (`Active`) до подключения реального источника заявок.

## Следующий учебный этап

Экспортируйте обновлённый workflow из n8n и замените этим экспортом файл `01-intake-foundation.json` — так в Git всегда будет проверенная n8n-версия, а не догадка о версии узла. Не включайте в экспорт credentials или секреты.

## Локальный Telegram вход

В текущем локальном workflow добавлен `Webhook` с методом `POST` и путём `telegram-lead`. Локальный polling-бот из `apps/telegram-bot` передаёт в него `source`, `contact` и `message`. Webhook соединён с **Нормализовать заявку**, поэтому далее используется тот же контур дедупликации и записи в Google Sheets.
